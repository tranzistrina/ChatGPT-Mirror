# Полный ChatGPT-Mirror для изолированной локальной сети (macOS, accessToken)

**Цель:** компьютеры локальной сети общаются **только с Mac-сервером**, а в интернет для общения с ChatGPT выходит **только Mac-сервер**.

Это **не** шлюз по OpenAI API-ключу. Используется оригинальный `accessToken`-совместимый `dairoot/chatgpt-gateway`, Redis и `cf5s`. Собранная панель Vue+Django — из **этого форка**, со сделанными исправлениями и RU/EN.

> **Ограничение:** код `chatgpt-gateway` и `cf5s` не опубликован. Их образы не проходили наш аудит, могут не запускаться или не работать с ChatGPT в 2026 году. Поэтому **проверенная сквозная работоспособность и отсутствие внешних запросов браузера не гарантируются**. Не используйте чужие или важные сессионные токены. AccessToken является секретом уровня учётной записи.

## Схема сети

```text
Клиент A (без интернета) ─┐
Клиент B (без интернета) ─┼── LAN ── Mac-сервер:50002 ──► Интернет ──► ChatGPT
Клиент C (без интернета) ─┘         │
                                    ├── Caddy + Vue + Django (из форка)
                                    ├── chatgpt-gateway (закрытый образ)
                                    ├── cf5s (закрытый образ)
                                    └── Redis
```

Маршруты: `/admin/` — панель управления; `/0x/` — Django API; `/` — чат, отданный оригинальным gateway. Внутренние порты Docker не опубликованы. Снаружи Mac виден только порт 50002 **на указанном LAN IP**.

## 1. Подготовьте Mac

Установите [Docker Desktop for Mac](https://docs.docker.com/desktop/setup/install/mac-install/) подходящей архитектуры (Apple Silicon или Intel), запустите его.

Проверьте:

```bash
docker version
docker compose version
git --version
python3 --version
```

Python 3.9+ достаточно для генератора секретов (для всего приложения в Docker ничего ставить в Python/macOS не надо). При отсутствии `git` установите инструменты Apple `xcode-select --install`.

```bash
cd ~
git clone https://github.com/tranzistrina/ChatGPT-Mirror.git
cd ChatGPT-Mirror
```

Если уже клонировали: `cd ~/ChatGPT-Mirror && git pull`.

## 2. Найдите локальный IP сервера

Для Wi-Fi интерфейса `en0` можно проверить:

```bash
ipconfig getifaddr en0
```

Если команда ничего не выводит, посмотрите интерфейсы:

```bash
networksetup -listallhardwareports
```

Используйте IPv4-интерфейса, подключённого к **закрытой LAN**, например `192.168.1.10`. Желательно закрепить этот адрес DHCP reservation на роутере или задать статически, чтобы не менялся.

## 3. Создайте безопасные настройки

```bash
python3 scripts/setup_lan_env.py
nano .env.lan
```

Установите **свой** адрес в двух полях (пример ниже нельзя слепо копировать):

```dotenv
LAN_BIND_IP=192.168.1.10
LAN_ALLOWED_HOSTS=192.168.1.10,localhost,127.0.0.1
```

Не меняйте автоматически созданные `DJANGO_SECRET_KEY` и `ADMIN_PASSWORD` без необходимости. Не публикуйте `.env.lan`.

## 4. Запустите полный стек (включая оригинальный gateway)

```bash
docker compose --env-file .env.lan -f docker-compose.lan.yml config --quiet
docker compose --env-file .env.lan -f docker-compose.lan.yml up -d --build
```

При первом запуске будут скачаны закрытые образы `dairoot/chatgpt-gateway` и `dairoot/cf5s`. На Apple Silicon для них используется эмуляция `linux/amd64`. Если образы недоступны, запуск не завершится. Отсутствие исходников не позволяет исправлять их внутреннюю логику.

Проверка работы:

```bash
docker compose --env-file .env.lan -f docker-compose.lan.yml ps
docker compose --env-file .env.lan -f docker-compose.lan.yml logs --tail=100 web gateway cf5s
```

Не выкладывайте логи публично: они могут содержать чувствительные сведения.

## 5. Откройте сайт с клиента без интернета

На любом компьютере в **той же сети**, где разрешено соединение с Mac, откройте в браузере:

- **Чат:** `http://192.168.1.10:50002/`
- **Панель:** `http://192.168.1.10:50002/admin/`

**Замените IP на свой**. Клиенту не нужен выход в интернет, но нужен маршрут к IP Mac и доступ на TCP 50002. Обычный браузер может автоматически попытаться обращаться к внешним ресурсам, встроенным в закрытый gateway. Поскольку исходный код gateway неизвестен, полностью автономный клиентский интерфейс **нужно проверить в Developer Tools → Network**. Если какие-то скрипты/шрифты/картинки подгружаются со внешних сайтов, без дополнительной доработки они не появятся.

Пароль от панели можно посмотреть **только на Mac**:

```bash
grep '^ADMIN_PASSWORD=' .env.lan
```

Администратор: `admin`. В интерфейсе панели далее добавьте **свой** действующий `accessToken` согласно логике оригинального проекта и распределите доступ пользователям; нельзя предполагать, что токен гарантированно будет принят в 2026 году.

Обратите внимание: проект изначально позволял делиться ChatGPT-сессией. Такая схема может противоречить действующим условиям пользования или создавать риск блокировки учётной записи. Кроме того, если нескольким людям нужен доступ, лучше обеспечить их отдельными учётными записями и не передавать персональный токен между пользователями.

## 6. Сетевая безопасность

1. **Не делайте проброс TCP 50002 на интернет** в роутере, не добавляйте публичный DNS или туннель через внешний сервис.
2. Mac должен сам иметь разрешённый исходящий доступ в интернет. Отсутствие интернета у клиентов не мешает серверной переадресации ChatGPT.
3. У клиентов должен быть доступ только к LAN IP Mac, не к Docker-подсетям или публичному интернету.
4. Соединение с `http://LAN_IP:50002` **не шифруется**: пароль, текст переписки и токены, передаваемые в браузере, могут быть видны в самой локальной сети. Для пользователей вне полностью доверенной физической сети **обязательно настройте HTTPS с доверенным локальным сертификатом**, либо сетевой VPN.
5. На macOS настройте брандмауэр / ACL роутера так, чтобы к TCP 50002 обращались только нужные локальные устройства. Привязка к LAN_IP ограничивает сетевой интерфейс, **но не является полноценным списком разрешённых клиентов**.
6. Сохраняйте резервные копии Docker volume `mirror_lan_sqlite`. Там будут `accessToken` и другие секреты без отдельного шифрования на уровне базы.

## 7. Остановка и удаление

```bash
docker compose --env-file .env.lan -f docker-compose.lan.yml down
```

Данные в Docker volumes сохраняются. **Не используйте `down -v`**, если не хотите безвозвратно стереть базу.

## А без Docker?

У открытой части проекта есть нативный запуск на macOS: [MACOS_SETUP_RU.md](MACOS_SETUP_RU.md). Но для **полного** accessToken-чата оригинальные `gateway` и `cf5s` распространяются **только готовыми Docker-образами**, а их исходников нет. Поэтому достоверной инструкции «полностью без Docker, но с тем же accessToken-функционалом» сейчас нет. Для такого режима сначала нужен проверяемый открытый аналог совместимого gateway.

## Что здесь не гарантируется

- Совместимость закрытого gateway с актуальным ChatGPT.
- Поддержка всех исходных возможностей UI и успешное обновление ChatGPT accessToken.
- Отсутствие браузерных запросов к внешним ресурсам со страницы закрытого шлюза.
- Безопасность закрытых образов и передаваемых им токенов.
- Соответствие использования общего персонального аккаунта условиям ChatGPT.

Это **экспериментальное развёртывание** в доверенной сети, а не проверенный эксплуатационный релиз.
